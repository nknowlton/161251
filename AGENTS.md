## Teaching-material editing guidance

This repository contains university teaching material. When working on lecture notes, slides, workshops, worked examples, Quarto files, R Markdown files, or other instructional prose, use the `lecture-editor` skill.

### Default behaviour for teaching material

Treat the lecture or teaching text as the primary artefact, not as incidental text inside a code repository.

When editing `.qmd`, `.Rmd`, `.md`, slide text, lecture notes, announcements, worked explanations, or similar material:

- Use the `lecture-editor` skill before making substantive prose edits.
- Improve weak prose properly rather than making only minimal-diff edits.
- Preserve the existing pedagogical scope, learning objectives, sequencing, examples, statistical interpretation, and level of difficulty unless Nick explicitly asks for a substantive teaching change.
- Do not silently remove concepts, simplify mathematics, change examples, alter assessment emphasis, reorder major sections, or redirect the lecture.
- If a change would materially affect pedagogy, scope, sequencing, examples, learning objectives, or conceptual framing, discuss it with Nick first.
- Continue making safe editorial improvements while leaving unresolved pedagogical choices unchanged.
- Do not replace actual lecture content with comments such as “consider adding an example here” unless Nick explicitly asks for critique rather than editing.
- Preserve executable code, YAML, citations, equations, anchors, cross-references, Quarto directives, and document structure unless changing them is required for the requested task.
- Use New Zealand spelling.
- Avoid generic AI prose, inflated transitions, repetitive summaries, unnecessary headings, and formulaic “key takeaway” language unless it genuinely improves the teaching.
- Preserve technical precision. In statistics and machine learning material, do not weaken distinctions such as association versus causation, prediction versus inference, estimate versus estimand, model assumption versus diagnostic evidence, or training performance versus generalisation.

### Discussion versus execution

When Nick is asking whether a lecture should change direction, whether material should be removed or moved, whether an example is pedagogically appropriate, or whether the scope is right, treat that as a discussion first rather than immediately editing files.

State the issue directly, give a concrete recommendation with reasoning, and surface meaningful trade-offs. Do not make major repository changes until the direction is clear.

When Nick asks to edit, polish, rewrite, shorten, clarify, or improve existing lecture material, proceed with the edit using the `lecture-editor` skill and preserve the teaching intent.

### Code and analysis

For code, data analysis, rendering, tests, package configuration, and other software-engineering tasks, follow the repository's existing conventions and normal Codex engineering practices.

Do not apply prose-editing rules mechanically to code.

When a task involves both code and teaching text, handle each according to its role: preserve technical correctness in code and apply the `lecture-editor` skill to the explanatory material.

### Communication style

Be direct, technically precise, and conversational.

Lead with the substantive answer or result.

Do not use em dashes.

## Architecture

This repository manages lecture content for Massey University course 161.251
(Regression Modelling). The system uses a single-source-of-truth pattern:

```
lecture-content/*.Rmd       ← Body content only (the single source of truth)
course/lectures.csv         ← Metadata: lecture numbers, weeks, titles, slugs, presenters
  ↓ child document include
lectures/*.Rmd              ← Standalone wrapper (YAML + setup + child include) — Knit in RStudio
slides/*.Rmd                ← Slidy/Beamer presentation wrappers for lectures 25-35
book/*.Rmd                  ← Bookdown chapter wrapper (heading + setup + child include)
book/_bookdown.yml          ← Explicit chapter order (committed, not generated per build)
  ↓ bookdown::render_book()
build/book/                 ← Rendered Bookdown HTML site
build/lectures/             ← Rendered standalone lecture HTML
build/slides/               ← Rendered personal presentation HTML/PDF
build/site/                 ← Assembled deployment directory
```

## Workflow

### Editing lecture content

1. Edit the relevant `lecture-content/<NN-slug>.Rmd` file
2. Preview by opening `lectures/<NN-slug>.Rmd` in RStudio and clicking **Knit**
3. For lectures 25-35, render slides with `Rscript scripts/render-slides.R <number>`
4. Or render the standalone lecture from command line: `Rscript scripts/render-lecture.R <number>`

### Building the full Bookdown site

```bash
Rscript scripts/render-book.R
```

Or directly:
```bash
cd book
Rscript -e 'bookdown::render_book("index.Rmd")'
```

### Rendering presentation slides

Presentation wrappers are generated for lectures marked `IncludeInSlides=yes`.
Slidy is the default output format. Beamer PDF output requires XeLaTeX.

```bash
Rscript scripts/generate-slide-wrappers.R
Rscript scripts/render-slides.R 26
Rscript scripts/render-slides.R 26 beamer
Rscript scripts/render-slides.R 26 all
```

Outputs are written to `build/slides/<slug>/`. Slidy HTML is published under
`/161251/slides/` by the GitHub Pages workflow; Beamer PDFs remain local.

### Restructuring the course (adding/removing/reordering lectures)

1. Edit `course/lectures.csv` — update lecture numbers, weeks, titles, slugs, presenters
2. If adding a new lecture, create `lecture-content/<NN-slug>.Rmd` with the body content
3. Set `IncludeInBook` and, when appropriate, `IncludeInSlides` in `course/lectures.csv`
4. Run `Rscript scripts/generate-book-wrappers.R` to regenerate book chapter wrappers and `_bookdown.yml`
5. Run `Rscript scripts/generate-slide-wrappers.R` to regenerate presentation wrappers
6. Create a `lectures/<NN-slug>.Rmd` wrapper when adding a standalone lecture
7. Commit all new/changed source and wrapper files

### lectures.csv format

```csv
LectureNo,Week,LectureTitle,Slug,Presenter,IncludeInBook,IncludeInSlides
1,1,Paper Overview,paper-overview,Jonathan Godfrey,yes,no
```

- **LectureNo**: Display number
- **Week**: Teaching week (1-12), or 0 for appendices
- **LectureTitle**: Full title shown in YAML and bookdown heading
- **Slug**: Kebab-case slug used for filenames: `sprintf("%02d-%s", LectureNo, Slug)`
- **Presenter**: Presenter name
- **IncludeInBook**: Whether to include in Bookdown (`yes` or `no`)
- **IncludeInSlides**: Whether to generate a Slidy/Beamer wrapper (`yes` or `no`)

### Validating the repository

```bash
Rscript scripts/validate-course.R
```

### Assembling the deployment site

```bash
Rscript scripts/render-book.R
Rscript scripts/assemble-site.R
```

## Bookdown configuration

- `_bookdown.yml`: `new_session: true` (each chapter runs in its own R session)
- Output directory: `../build/book`
- Chapter files are flat in `book/` (not in a subdirectory) because `new_session: true`
  requires all input files to be directly under the book root
- Chapters are ordered explicitly via `rmd_files`

## Common issues

- **Duplicate chunk labels**: Some lecture content files have duplicate chunk
  labels within a single file. knitr auto-deduplicates these (appending `-1`,
  `-2`, etc.), so they render correctly but produce warnings. The validation
  script reports these as warnings, not errors.
- **Missing data files**: Add the required file to `/data/` and commit it.
- **Missing R packages**: Install with `install.packages(c("DescTools", "car",
  "emmeans", "nlme", "lmtest", "glmnet", "patchwork", "kableExtra", "gridExtra",
  "GGally", "broom.mixed", "maps", "ggrepel"))`
- **Beamer won't compile**: Ensure XeLaTeX is installed and available as
  `xelatex` on `PATH`.
- **Bookdown won't compile**: Run `Rscript scripts/render-book.R` from the repo
  root, which changes into `book/` automatically.
